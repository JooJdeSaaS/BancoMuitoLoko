a) SQL Injection (Injeção de SQL)
- Categoria OWASP: A03:2021 – Injection.
- Explicação do Risco: O código utiliza f-strings para inserir diretamente a variável user_id em uma consulta SQL sem qualquer sanitização ou uso de prepared statements. Isso permite que um atacante manipule a query original.
- Exemplo de impacto: Se um usuário enviar '1 OR 1=1' como user_id, a instrução se tornaria DELETE FROM users WHERE id = 1 OR 1=1, resultando na exclusão de todos os usuários do banco de dados, em vez de apenas um.

b) Identification and Authentication Failures (Falhas de Identificação e Autenticação)
- Categoria OWASP: A07:2021 – Identification and Authentication Failures.
- Explicação do Risco: O uso de credenciais fracas ou padrões (como o usuário "admin" e a senha "password123") em arquivos de configuração é uma falha grave de segurança.
- Exemplo de impacto: Atacantes podem facilmente realizar ataques de força bruta ou simplesmente usar senhas conhecidas de fábrica/padrão para obter acesso administrativo total ao banco de dados clinica_db, expondo todos os dados sensíveis.

c) Broken Access Control (Quebra de Controle de Acesso)
- Categoria OWASP: A01:2021 – Broken Access Control.
- Explicação do Risco: O sistema busca o perfil de um usuário baseando-se apenas no parâmetro id enviado via URL (request args), sem validar se o usuário autenticado tem permissão para visualizar aquele ID específico. Esta falha é conhecida como IDOR (Insecure Direct Object Reference).
- Exemplo de impacto: Um usuário logado com o id=10 pode simplesmente alterar a URL para ?id=11 e visualizar o perfil de outra pessoa, pois o sistema não verifica se o cookie de sessão pertence ao dono do recurso solicitado.
